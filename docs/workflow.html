How the translate workflow runs

One command sends your source files to a Lokalise Vantage file project, waits for the AI translation, and saves only the files from that run.

This is the vantage-translate client in this repository. The same command runs on your machine and in GitHub Actions.

The short version

getting-started.md and file2.md go in together. Spanish comes back as getting-started.es.md and file2.es.md. Nothing else in the project is downloaded.

Before it starts

1

You give it a token and a project

The client needs a read/write Lokalise API token and the UUID of a Vantage file project. On your machine, put both in .env in this folder. The command also finds that file if you start it from a subfolder such as source-lang. .env is not committed.

VANTAGE_API_TOKEN=your-token
VANTAGE_PROJECT_ID=your-project-uuid

In GitHub, the token is a repository secret named VANTAGE_API_TOKEN. The project id is a repository variable named VANTAGE_PROJECT_ID. The workflow does not use a GitHub Environment, so environment secrets are not read.

Keep in mind: the token is sent only to api.lokalise.com. The file upload and the translated-file download use temporary storage links, and those requests do not include the token.

2

You point it at the files

--input is a file or a folder. Repeat the flag to send more than one path. A folder is searched, including subfolders. A file you name directly must be a supported type. Inside a folder, other files are skipped.

py -3 -m vantage_client --input source-lang --output translated
  • Supported types: DOCX, PPTX, XLSX, HTML, Markdown, and IDML.
  • Each file must be 50 MB or smaller.
  • Two files cannot share the same name, even in different folders. Vantage tells uploads apart by file name, ignoring letter case.

Keep in mind: --output is the folder where translations are written. The default is translated.

3

It reads the project’s target languages

The first API call loads the project. The project must be a file project. The client takes every target language on that project. The base language is the language you wrote in, so it is not exported.

API call: GET /v1/projects/{projectId}

To ask for fewer languages, pass --locales. de-DE and de_de match the same language. The spelling stored on the project is the one used later in the file names.

py -3 -m vantage_client --input source-lang --locales es --output translated

Keep in mind: with no --locales, a project whose only target is Spanish downloads es and nothing else.

The files go in

4

Several files go in as one batch

Every file in the run is registered together, up to 100 files. That registration returns one batch id. The later import uses that same id, so the files are imported once, not once per file.

API call: POST /v1/projects/{projectId}/uploads with every file’s name, type, size, and MD5 checksum.

A run of 140 files becomes two batches: the first 100, then the remaining 40. Each batch is uploaded, confirmed, and imported before the next one starts. The download at the end still covers every file from the run.

Keep in mind: getting-started.md and file2.md are one batch and one import.

5

Each file is uploaded, then the batch is confirmed

Vantage answers the registration with a temporary upload link for each file. The client posts the file there, then tells Vantage the batch is complete. It then checks the batch until every file in this run is UPLOADED. A status of UPLOAD_FAILED stops the run.

API calls: upload to the temporary link, then POST /uploads/actions/complete with the batch id, then GET /uploads?filter-batch-id=… until the files are parsed.

Keep in mind: confirming the batch does not import it yet. Parsing only means Vantage has accepted the file bytes.

6

The batch is imported, and each file gets an item id

One import call brings the whole batch into the project as source content, in the project’s base language. Translation starts on its own after that. The client checks the same batch until each file is IMPORTED.

API calls: POST /v1/projects/{projectId}/imports with the batch id, then GET /uploads?filter-batch-id=….

The item id is not known when the file is staged. It appears on the upload record only after the status is IMPORTED. The client keeps the item id of each file from this run and ignores every other upload in the project.

Keep in mind: the item id is how the download stays limited to the files you just sent.

The AI translates

7

It waits for the AI, and not for reviewers

The client checks the import’s translation status about every 5 seconds. While a language is TRANSLATING, it keeps waiting. When the AI draft is ready, it moves on and downloads that draft.

API call: GET /v1/projects/{projectId}/translation-statuses/{importId}

  • TRANSLATING means the AI is still working. Keep waiting.
  • PENDING_REVIEW means the AI is done and a person may still review it. Download now.
  • COMPLETED means the language is finished. Download now.
  • FAILED stops the run.

Each wait has its own limit of 30 minutes: parsing the upload, finishing the import, translating, and building the export. Pass --timeout to change that limit, in seconds.

Keep in mind: if the project uses human review, the command does not sit and wait for reviewers. It downloads the AI files as soon as they are ready.

The files come back

8

It exports only the items from this run

The export lists each item id from this run, with the target languages chosen in step 3. It does not ask for the whole project, and it does not send a language list on its own. Older uploads that happen to sit in the same project stay out of the download.

API calls: POST /v1/projects/{projectId}/exports, then GET /exports/{exportId} until the status is COMPLETED.

If an item has no translated content in the requested language, Vantage leaves that file out of the bundle. The command still saves the files that did come back, and it prints the names that were missing.

Keep in mind: a failed export stops the run. The client does not save a partial download from a failed export.

9

Vantage names the files, and the client checks those names

The export request does not include a file name. Vantage builds one from the original name and the project’s locale: the locale is inserted before the extension.

You sentSpanish file
getting-started.mdgetting-started.es.md
file2.mdfile2.es.md
guide.docxguide.de-DE.docx

One produced file is downloaded as that file. Several produced files arrive as one ZIP, with those names at the top and no folders. The client writes them into --output. A name it did not expect stops the run, and that file is not saved. A path that tries to leave the output folder is rejected the same way.

API call: GET /exports/{exportId}/download-url, then a download of that temporary link with no API token.

Keep in mind: if you asked for two files and Vantage produced only one, you still get that one file. The log names the file that was left out.

10

GitHub Actions runs the same command

The workflow in .github/workflows/translate.yml starts when you run it by hand. It does not send the whole source-lang folder. On master, it sends the files that changed in the latest commit. On any other branch, it sends the files that differ from master. Each of those paths is passed on its own, and a run with no changed files stops before calling Vantage.

  • The runner is Ubuntu, with Python 3.12.
  • The token comes from the repository secret. The project id comes from the repository variable.
  • The job is allowed 60 minutes. Inside the command, each wait is still 30 minutes.
  • When the command finishes, the workflow opens a branch named translations/, the triggering branch, the GitHub run id, and the attempt number. A run on master opens a branch such as translations/master-18492736421-1.
  • It commits translated/ on that branch and opens a pull request back to the triggering branch. Each run gets its own pull request, so an earlier unmerged translation stays where it is.

Keep in mind: translated/ stays out of ordinary local commits. The workflow adds it only on the translation branch. A push that changes only that folder does not start another translation run.
